# Поддержка устройств

Общий API и plugin runtime находятся в `betteryam-runtime`. Каждый daemon
подключает свой hardware adapter. Приведённые ниже сведения относятся к
профилям, которые сейчас есть в репозитории; они не обещают наличие одинаковых
возможностей на других моделях или прошивках.

## Профили устройств

| Профиль | LED | Порядок каналов | Сенсор proximity |
| --- | --- | --- | --- |
| `yandexmini` | 6 RGB LED | BGR | Профиль объявляет поддержку |
| `yandexmicro` (Station Lite) | 3 RGB LED | RGB | Не поддерживается |

Mini использует собственный I2C LED backend. Lite записывает значения в
обнаруженные sysfs LED nodes. Это детали adapter-ов, они не являются частью
Lua API. Для LED-кольца плагины должны использовать `device.led_count` и
capabilities `led.ring.rgb` и `led.ring.<count>`, а не предполагать конкретное
количество элементов или порядок каналов.

## Capability-driven доступность

Для операций, зависящих от системных интерфейсов или hardware, проверяйте
boolean capabilities из `GET /api/device` либо соответствующий метод
`alice.<api>.is_available()`. Capability может зависеть от обнаружения
устройства, утилит, прав доступа и безопасного runtime-состояния. Наличие
маршрута или Lua-метода само по себе не означает, что операция доступна.

Sensors должны обнаруживаться и перечисляться через
`alice.sensors.list()`; не полагайтесь на идентификаторы, характерные для
отдельной модели. Bluetooth status и power — отдельные возможности; более
широкие операции, такие как scan, pair и connect, должны объявляться только
при наличии подходящего backend. Аналогично проверяйте capabilities для
volume, audio, display, clock, input, IPC и Wi-Fi.

## Добавление устройства

Новая модель добавляется отдельным daemon adapter-ом, который предоставляет
общему runtime профиль и backend-ы. Общий API не должен содержать проверок
модели, аппаратных адресов, путей sysfs или фиксированного числа LED.
Практические шаги описаны в [руководстве по добавлению устройства](./ADDING_DEVICES.md).
